# The 78 Power Map and Scenario Simulator

A two-tab workshop prototype for the Building with Context workshop, about The 78 (PD 1434) in Chicago.

1. **Power map:** who holds power over the project. Height is a computed Katz power score, and you can toggle between formal power and real influence.
2. **Scenario builder:** pick a decision and see who gains and who loses, the range of outcomes, and where in the approval pipeline nonprofits can still act.

> Prototype. Uses illustrative data. Not a forecast.

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
```

Everything is bundled at build time, so the app works offline. No backend, no network calls.

```bash
npm test           # model tests (Vitest)
npm run check-data # validates /data: tie endpoints, evidence/source fields, weights in [-1, 1]
npm run build      # check-data + typecheck + production build into dist/
```

## Deploy

It's a static site, so any static host works.

- **Netlify:** connect the repo. `netlify.toml` sets `npm run build` and publishes `dist/`.
- **Vercel:** import the repo. `vercel.json` sets the same thing.

## Editing the content

All text, ties and weights live in flat JSON in `data/`, so you don't need to touch the code. Every record carries `evidence` (`documented`, `press`, `interview` or `synthetic`) and `source`. Run `npm run check-data` after editing.

| File | What it holds |
| --- | --- |
| `actors.json` | Nodes: people, bodies, organizations, non-human actants |
| `ties.json` | Directed ties with type, layer (`formal`, `real` or `both`), strength 1–3, flows and amount |
| `tie_types.json` | **Which side of each tie type gains standing.** The most consequential modeling choice. |
| `channels.json`, `segments.json`, `sensitivities.json` | Effect channels, who bears them, and how strongly |
| `decisions.json` | Preset scenarios, counter-levers and the "signal hook" event for each |
| `stages.json` | Approval pipeline with dates, status and the interventions still open |
| `cases.json` | Comparable developments shown on case cards |
| `params.json` | Katz α/β, number of runs, seed, and the slider defaults |
| `areas.json`, `geo/*.json` | Generated by `npm run preprocess` (see below) |

## Preprocessing (run once)

```bash
SANDBOX="../Data Sandbox" npm run preprocess
```

This simplifies the sandbox GeoJSON into `data/geo/` (132 KB total) and clips city-owned parcels to areas 31, 33 and 34. It also joins Tree Equity Score block groups to community areas through the 2010 tract table and writes `data/areas.json`. The generated files are committed, so deploys don't need the sandbox.

**Don't commit the Data Sandbox.** The Plan Commission written-comment PDFs contain residents' names, addresses and email addresses.

## The math

Everything is in `src/model/` and covered by tests.

- **Power (`power.ts`).** Each tie adds standing to one side, according to `tie_types.json`. The score is Katz status on each layer, `x = α Sᵀx + β`, scaled to 0–1. α is capped at 0.85/λ_max if needed so the series converges. Each layer also gets Krackhardt's hierarchy index, computed on reachability. The leverage hint tries one new tie from each of the top 10 actors and lists the 3 that raise the selected actor's score most.
- **Scenarios (`scenario.ts`).** `E_s = Σ_c Δ_c · w_cs · (1 + v_s·1[Δw < 0])`. Decisions stack by adding their shifts. Three knock-on links are applied once from the direct shifts. Counter-levers adjust the weights before the sum. 500 seeded runs give each segment a median, a 10th–90th percentile band and the share of runs in which it loses. The "because" line is built from the two largest terms.
